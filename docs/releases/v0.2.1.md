# whirl v0.2.1

A patch release for the command-line tool. Two changes, both to `whirl` itself:
the flag that answers without anything else running, and the subcommand that
answers about the client before it talks to a daemon.

Released together with the app's v0.2.1, which pins this release in its
installer: shipping one without the other leaves the app pointing at a daemon
that is not there.

## What changed

- **`whirl --version` (and `-V`) answers with the client's own version and
  exits, with no daemon, no config and no socket.** Before this, the only way to
  ask a version question was the `version` subcommand, which reaches for the
  daemon first, so a user with a stopped daemon learned nothing about the tool
  they were running. The one-line flag now works on any machine the binary is
  on.

- **`whirl version` prints the client's own facts first, then the daemon's
  answers when a daemon is there.** The order is: the client's version, the
  protocol version it speaks and the platform it was built for, followed by
  whatever the daemon answers when the socket is reachable. When the daemon is
  not reachable, the client's three lines are still printed, the socket error
  follows them, and the command exits `2` so a script can tell "no daemon" from
  "the daemon said no". The daemon's own words are unchanged and remain its own.

Both are covered by the repository's suite: the argv tests drive the flag and
the subcommand against a real process, and the control-socket tests assert the
daemon's half of the greeting and the version answer.

## Config and protocol changes

Checked rather than assumed, against v0.2.0:

- **The config schema did not move.** `config_schema` is `1` in v0.2.0 and `1`
  here. No key was added, removed, renamed or given a different default.
- **The protocol version did not move.** `PROTOCOL_VERSION` is `2` in v0.2.0 and
  `2` here; no verb was added and no error code changed. The daemon already
  answered a version request; this release changes only what the client prints
  around that answer.
- **The state directory did not move.** The config, the state files, the socket,
  the cache and the log are at the paths `docs/spec/state-and-cache.md` gives,
  unchanged.
- **One output changed, and it is the point of the release:** `whirl version`
  now prints the client's lines before the daemon's. Anything that parses that
  output by line position should read the fields it needs instead of counting
  lines.

## Upgrades and known issues

- **Upgrading from v0.2.0: replace the binaries.** That is the whole upgrade;
  nothing in the state directory or the config file has to change. A running
  daemon holds its lock and a new one refuses to start while the old process
  holds it, so stop the daemon you have (through `whirl daemon stop`, or the way
  you started it) before replacing `whirld` under it.
- **Known issue: `whirl version` exits `2` when the daemon is unreachable, and
  that is deliberate.** The client's lines are on stdout before the exit, so the
  information is there for a reader and the exit code is there for a script.
- **Known issue: `whirl daemon install` is macOS only.** On Windows and Linux it
  prints one sentence naming the platform and exits `1`. Those units are
  deferred, not forgotten.
- **Known issue: the unit names an absolute path.** The unit it writes points at
  the `whirld` beside the `whirl` that ran the command, so extract the archive
  somewhere it will stay. Moving the binaries afterwards means running `whirl
  daemon install` again from the new location.
- **Deferred:** Developer ID signing and notarization for the macOS artifact, any
  installer or `.pkg`, a Windows signing route, Linux distribution packages, and
  the Task Scheduler and `systemd --user` units.
